# MyStatClips website

The approved MyStatClips design, prepared as a **standalone static website for GitHub Pages**. No API server, database, mobile project, RevenueCat setup, account system, or secrets are needed.

The separate website repository is **[np94dszr2r-pixel/mystatclips-website](https://github.com/np94dszr2r-pixel/mystatclips-website)**. The included GitHub Pages publishing workflow is manual: pushing files alone does not publish the website. No custom domain or DNS is configured by this project.

The connected GitHub integration cannot write workflow files. The GitHub repository includes `pages-workflow.yml` as a template; install it as `.github/workflows/pages.yml` using GitHub's web editor, then run it. See `GITHUB-PAGES.md` for the exact steps.

## What is included

- Home page with the approved recording demonstration, nine sport icons, and sample player card.
- Support, How-To landing, Quick Start Guide, Complete User Guide, Privacy Policy, and Terms of Use pages.
- Unmodified official logo and the approved AI-generated fictional athlete photo.
- Static-page builds, link/asset/anchor checks, and a manual GitHub Pages workflow.
- This setup guide and `GITHUB-PAGES.md` for repository and custom-domain setup.

The exploratory player walkthrough is **not included**: it was not approved for the finished website.

## Run and build

Use Node.js 22.12 or newer and pnpm 10.26.1. This project has its own package manifest, TypeScript settings, assets, and lockfile; it does not depend on the surrounding workspace.

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm run dev
```

Outside Replit, the development server defaults to port 5173. In Replit, use the existing **MyStatClips Website** preview; its managed workflow supplies its port and preview base.

```sh
# Local website or a custom-domain build:
WEBSITE_BASE_PATH=/ pnpm run check

# A GitHub project-site build — replace the example with your repository name:
WEBSITE_BASE_PATH=/your-repository-name/ pnpm run check

# Serve the matching completed build locally:
WEBSITE_BASE_PATH=/your-repository-name/ pnpm run serve
```

On Windows PowerShell, set `$env:WEBSITE_BASE_PATH="/your-repository-name/"` before the commands.

The completed website is in **`dist/`**. It contains seven rendered HTML pages, plus assets and `.nojekyll`. The How-To pages also have directory entries at **`/how-to/`**, **`/how-to/quick-start/`**, and **`/how-to/complete-guide/`**, so direct links and refreshes work on GitHub Pages without a server-side router. Existing `.html` links still work. All paths honor the configured website base.

The short Quick Start and detailed Complete Guide share content in `src/pages/how-to-content.ts`. Instructions were checked against the current app source. The three guide screenshots are current **mobile web-preview captures**, explicitly labelled; they are not native camera or physical-device test evidence. Keep the guide text aligned with the app version users actually receive.

Page HTML entry files are generated by `scripts/create-entries.mjs`; update titles, descriptions, fonts, or indexing rules there rather than editing generated entries. Editable page content is in `src/pages/`.

## Before public launch

These are intentionally unfinished, not broken integrations:

1. **Kit:** the launch-list section loads the owner's embed using its unchanged public script URL and form ID. Kit owns the fields, validation, submission, and confirmation. Signups go directly to Kit; this website does not store them. If the script is blocked, visitors see a loading-error message, retry control, and a link to the owner's public Kit signup page rather than a fake signup success. The public form page was visually verified; the embed was blocked in the automated preview browser. Build checks verify wiring, not live subscriber collection. Verify a real submission with an owner-approved test email before public launch.
2. **Legal pages:** replace placeholders with reviewed, approved Privacy Policy and Terms text. No legal promises were invented.
3. **Product evidence:** the How-To guides include current, labelled app web-preview screenshots. A native iPhone walkthrough/video can be added when supplied. Homepage recording and player-card demonstrations remain clearly labelled demo content.
4. **App Store and social links:** remain “coming soon” until real links are supplied.
5. **Pricing:** not published or invented.
6. **Search indexing:** generated pages are `noindex, follow` while these launch items are unfinished. Once the public site is approved, change that rule in `scripts/create-entries.mjs` and rebuild. Set any canonical/social absolute URLs only after the public URL is known.

The approved fonts load from Google Fonts, matching the preview, and the signup form loads from Kit. These create third-party browser requests; disclose the actual Google Fonts and Kit behavior in reviewed website privacy text. No separate analytics, email database, or mailing-list backend was added.

## Isolation

All website source lives in this directory. Mobile recording, Swift, Recovery, RevenueCat, and mobile packages have not been changed. Do not copy the monorepo, mobile app, API server, or workspace secrets into the website repository.
